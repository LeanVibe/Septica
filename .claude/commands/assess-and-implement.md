# Assess & Implement Workflow

Comprehensive assessment and implementation workflow for iOS app development.

## Usage
```
/assess-and-implement
```

## Workflow Steps

### 1. Status Assessment
- Take screenshot of current app state (simulator or device)
- Analyze app logs for errors, warnings, performance issues
- Check git status and recent commits
- Review current todo list and progress

### 2. Technical Analysis
- Identify current blockers and issues
- Assess code quality and architectural concerns
- Check build status and compilation health
- Evaluate UI/UX and visual quality

### 3. Plan Update
- Update implementation plan based on findings
- Prioritize most critical issues
- Break down complex tasks into actionable items
- Set clear success criteria

### 4. Implementation Sprint
- Execute highest priority fixes
- Build and test changes incrementally
- Verify fixes work on target devices
- Commit progress with clear documentation

### 5. Progress Validation
- Take updated screenshots showing improvements
- Run automated tests where available
- Validate on both simulator and physical devices
- Document achievements and remaining work

### 6. Next Steps Planning
- Identify next most impactful improvements
- Update project roadmap
- Set expectations for following iterations
- Save context for future sessions

## Best Practices

### Assessment Phase
- Always capture current state before making changes
- Use both visual inspection and log analysis
- Consider user experience from fresh perspective
- Check for edge cases and error conditions

### Implementation Phase
- Focus on one major issue at a time
- Test changes immediately after implementation
- Commit working improvements incrementally
- Maintain backward compatibility where possible

### Quality Gates
- Build must succeed before deployment
- No new crashes or critical errors
- Visual improvements must be measurable
- Performance should not regress

### Documentation
- Record what was changed and why
- Include before/after comparisons
- Note any trade-offs or compromises made
- Update relevant documentation files

## Success Criteria

Each workflow iteration should achieve at least one of:
- Fix a critical bug or crash
- Implement a significant new feature
- Improve visual quality or user experience
- Enhance performance or stability
- Complete technical debt cleanup

## Context Preservation

- Save key findings to project documentation
- Update PLAN.md with current status
- Commit all changes with descriptive messages
- Prepare handoff notes for future sessions
